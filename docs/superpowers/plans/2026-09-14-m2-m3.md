# Value Story M2 + M3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give the tool an evidence pipeline (M2) and a measured visual gate (M3), so a value case can be authored from real documents with citations that cannot be fabricated, and so layout quality is verified by measurement rather than assertion.

**Architecture:** Extraction is an AGENT task, not a parser. The tool's job is to turn documents into text an agent can read, record exactly what was read in a manifest, and refuse any citation naming a source absent from that manifest. Judgment about whether a number is *measured* or merely *asserted* stays with the agent, guided by `SKILL.md`. M3 adds a Playwright gate that loads the delivered HTML without re-rendering it and measures what a human would otherwise eyeball.

**Tech Stack:** Node 23.5.0 (ESM, `.mjs`), built-in `node:test`, `node:zlib` for OOXML containers, Playwright as a devDependency (M3 only), `pdftotext` and `textutil` as OPTIONAL external tools.

**Spec:** `docs/superpowers/specs/2026-09-13-value-story-design.md` §3, §5.2, §6.5, §7
**Predecessor:** `docs/superpowers/plans/2026-09-13-value-story.md` (M0+M1, complete, 40 commits, 156 tests)

## Global Constraints

- **`dependencies` stays `{}`.** Playwright is a devDependency. `pdftotext` and `textutil` are optional EXTERNAL binaries — never npm packages, never required for the renderer or validator to run.
- **The renderer's zero-dependency guarantee is absolute.** Nothing under `src/render/`, `src/validate.mjs`, `src/deliver.mjs`, `src/semantic.mjs`, `src/reconcile.mjs` or `src/diagnostics.mjs` may gain an import that is not `node:*` or a local file.
- **Node >= 22.** ESM only; `.mjs`.
- **Never describe a non-zero exit as success.**
- **No hex colour outside `src/render/tokens.mjs`.**
- **Never hand-edit `generated/` or `.github/`** — regenerate via their scripts.
- **`schemas/value-case.schema.json` is FROZEN.** M2 adds a second schema for the manifest; it does not alter the value-case schema.
- **All fixtures are synthetic.** Never commit anything resembling real confidential material.
- Tests must not mutate the working tree. `npm test` must leave `git status` clean.

# MILESTONE 2 — Extraction and the manifest

### Task 15: A zero-dependency OOXML reader

`.docx` and `.pptx` are ZIP archives of XML. Node's `zlib.inflateRawSync` decompresses their entries, so no npm package is required.

**Files:**
- Create: `src/ingest/container.mjs`
- Create: `src/ingest/ooxml.mjs`
- Test: `test/ingest-ooxml.test.mjs`

**Interfaces:**
- Produces:
  - `listEntries(buffer) => Array<{name, offset, compressedSize, uncompressedSize, method}>`
  - `readEntry(buffer, entry) => Buffer`
  - `docxText(buffer) => string` — paragraph text in document order, one paragraph per line
  - `pptxText(buffer) => string` — slide text in slide order, prefixed `Slide N:`

Build the two test fixtures in the test's setup with a small zero-dependency ZIP writer, so nothing binary is committed and nothing is downloaded.

- [ ] **Step 1: Write the failing test**

Cover: a stored (method 0) entry and a deflated (method 8) entry both read correctly; `docxText` returns paragraphs in document order; `pptxText` sorts slides NUMERICALLY (`slide2` must not follow `slide10`); XML entities (`&amp;`, `&lt;`, `&#233;`) decode; `<w:tab/>` becomes whitespace rather than joining two words; a non-ZIP buffer throws a clear Error rather than yielding garbage.

- [ ] **Step 2: Run test to verify it fails**

Run: `node --test test/ingest-ooxml.test.mjs`

- [ ] **Step 3: Implement**

`container.mjs` — locate the End of Central Directory record, walk the central directory, inflate method 8 with `zlib.inflateRawSync` and slice method 0. Handle the data-descriptor case. Reject Zip64 with a clear message rather than misreading it.

`ooxml.mjs` — for `.docx`, read `word/document.xml`, treat `<w:p>` as paragraphs, concatenate their `<w:t>` runs. For `.pptx`, read every `ppt/slides/slideN.xml`, sort numerically by N, concatenate `<a:t>` runs. Decode XML entities. Strip tags without swallowing adjacent text.

- [ ] **Step 4: Run test to verify it passes**
- [ ] **Step 5: Commit**

### Task 16: `vs ingest` — documents in, text and manifest rows out

**Files:**
- Create: `src/ingest/plain.mjs`, `src/ingest/external.mjs`, `src/ingest/ingest.mjs`
- Modify: `bin/vs.mjs` — add the `ingest` command
- Test: `test/ingest.test.mjs`

**Interfaces:**
- `ingestFile(path) => { path, title, kind, sha256, bytes, text, warnings[] }`
- `ingestDir(dir, {recursive}) => { documents: [...], skipped: [{path, reason}] }`
- CLI: `vs ingest <path...> --out <dir> [--json]`

**Behaviour:**
- `.docx`/`.pptx` via Task 15. `.txt`/`.md` read directly. `.eml` — parse `Subject`, `From`, `Date` headers, then decode the body, handling `quoted-printable` and `base64` transfer encodings and preferring `text/plain` over `text/html` when both exist.
- `.pdf` — shell out to `pdftotext` IF on PATH. `.rtf`/`.doc` — `textutil` IF present. When the binary is absent, DO NOT fail the run: skip the file, record it in `skipped` with a reason naming the binary and how to install it, and continue.
- `kind` maps to the `evidence[].kind` enum: `doc`, `email`, `dataset`, `interview`. Infer conservatively — `.eml` is `email`, `.csv` is `dataset`, everything else is `doc`. Never guess `interview`; the agent corrects it.
- `sha256` is over the FILE BYTES, not the extracted text, so the manifest identifies the document even if extraction later improves.
- Writes one `.txt` per document into `--out`, named deterministically, and prints the manifest rows.

- [ ] **Step 1: Write the failing test** — each supported extension; an `.eml` with quoted-printable; a missing external binary producing a skip rather than a crash; `sha256` stable across two runs; directory ingest sorted by path for determinism; an unsupported extension skipped with a reason.
- [ ] **Step 2: Run to verify it fails**
- [ ] **Step 3: Implement**
- [ ] **Step 4: Run to verify it passes**
- [ ] **Step 5: Commit**

### Task 17: The evidence manifest and `evidence/not-in-manifest`

This is the task that makes a fabricated citation impossible. Spec §5.2.

**Files:**
- Create: `schemas/evidence-manifest.schema.json`
- Create: `src/manifest.mjs`
- Modify: `src/validate.mjs`, `scripts/generate-validators.mjs`, `bin/vs.mjs` (`--manifest <path>` on `validate` and `deliver`), spec §5.1
- Test: `test/manifest.test.mjs`

**Interfaces:**
- `readManifest(path) => { documents: [{path, title, kind, sha256, bytes, ingested_at}] }`
- `manifestDiagnostics(doc, manifest) => Diagnostic[]`

**Behaviour — get this exactly right:**
- With NO manifest supplied, `evidence/not-in-manifest` does NOT fire. The check is opt-in, because hand-authored cases remain legitimate. Whether a manifest was supplied MUST appear in the delivery receipt, so "citations were verified" is never claimed falsely.
- With a manifest, every `evidence[]` entry must correspond to a manifest document, matched on `title`. Report the closest manifest titles in `evidence` so the repair is mechanical.
- `supportedFixes` names the JSON Pointer of the offending evidence entry.
- A manifest listing documents the case does not cite is FINE and must not warn. Reading more than you cite is normal.
- A manifest whose recorded `sha256` no longer matches the file on disk produces `evidence/manifest-stale`.

- [ ] **Step 1: Write the failing test** — no manifest → silent; all titles resolve → clean; one absent → fires with the right pointer and candidate list; extra unused documents → clean; changed file → `evidence/manifest-stale`.
- [ ] **Step 2: Run to verify it fails**
- [ ] **Step 3: Implement**, regenerate validators, update spec §5.1
- [ ] **Step 4: Run to verify it passes**; `git diff --exit-code generated/` clean after regeneration
- [ ] **Step 5: Commit**

### Task 18: Extraction guidance in `SKILL.md`

The hardest part of M2 is not parsing. It is an agent deciding whether a number was MEASURED or merely ASSERTED. That decision is guided here.

**Files:**
- Modify: `SKILL.md` (must stay under 150 lines — trim elsewhere if needed)
- Regenerate: `.github/` via `npm run build:adapters`
- Test: `test/skill.test.mjs`

**Content to add, inside the contract delimiters:**
- The ingest → review → author → validate → deliver flow, with commands.
- **Tier assignment rules.** A figure is `measured` only when the cited source REPORTS it as an observation — a dataset, a metered reading, a counted extract. A figure stated in a deck, a status update, a proposal or an email with nothing behind it is `estimated`, and it needs an owner. When neither holds, it is `qualitative`, or it is not a claim at all.
- **The five leadership questions must be actively hunted**, especially risk and reach, which sit further from the surface of a status report than cost and time do.
- **Never author an `evidence` entry for a document not in the manifest** — already a prohibition, now enforced.
- Keep every existing prohibition verbatim.

# MILESTONE 3 — The visual gate

### Task 20: `vs visual-check` — overflow at three viewports

**Files:**
- Create: `scripts/visual-check.mjs`
- Modify: `package.json` (Playwright devDependency, `visual-check` script), `bin/vs.mjs`
- Test: `test/visual-check.test.mjs`

**Interfaces:**
- `visualCheck(htmlPath, {viewports}) => { ok, findings: [...] }`
- CLI: `vs visual-check <output.html> [--json]`

**Behaviour:**
- Loads the DELIVERED file via `file://`. It must NOT re-render, re-validate or modify it — spec §6.5. Assert this by hashing the file before and after.
- Viewports 1440×900, 1600×1000, 1920×1080.
- At each: `document.documentElement.scrollWidth <= window.innerWidth`. Horizontal overflow is a finding; vertical scrolling is normal and is NOT.
- Findings carry the viewport, the overflow in pixels, and the selector of the widest offending element.
- Playwright stays a devDependency, and `visual-check` must fail with a clear actionable message when it is absent — never a stack trace.

- [ ] **Step 1: Write the failing test.** Use two tiny synthetic HTML files in a temp dir — one that fits, one with a deliberately 3000px-wide element — and assert the gate passes the first and fails the second with a pixel measurement. Do NOT run the unit test against a project artifact; that would couple the gate to the renderer.

### Task 21: Contrast, collision, and hero-above-the-fold

**Files:**
- Modify: `scripts/visual-check.mjs`
- Test: `test/visual-check.test.mjs`

**Behaviour:**
- **Contrast:** compute the WCAG contrast ratio of rendered text against its effective background. Flag below 4.5:1 for body text, 3:1 at or above 24px. Report the element, both colours, and the ratio. Resolve the background by walking ancestors to the first non-transparent one — do not assume `body`.
- **Collision:** flag any two text-bearing elements whose bounding boxes overlap by more than 2px on both axes. Require both to have non-empty text so decorative overlaps are excluded.
- **Above the fold:** at the smallest viewport, `.vs-hero__figures` must sit fully within the first screen. Skip the check when no hero exists rather than failing — the no-hero path is legitimate.

- [ ] Steps 1-5, each check with its own synthetic pass and fail fixture.

### Task 22: Graduated repair guidance and the delivery contract

**Files:**
- Modify: `scripts/visual-check.mjs`, `SKILL.md` (+ regenerate `.github/`), spec §5.1 and §6.5
- Test: `test/visual-check.test.mjs`, `test/skill.test.mjs`

**Behaviour:**
- Findings use the standard envelope from `src/diagnostics.mjs`: `layout/overflow`, `layout/collision`, `layout/contrast`, `layout/hero-below-fold`.
- **Graduated fixes that say what NOT to do:**
  - ≤ 40px over: tighten one gap or padding by 20-40px; do not remove content
  - 41-200px over: move a supporting element to the next chapter; do not shrink the hero numeral
  - over 200px: the layout is wrong for this content; report it rather than compressing
- **`SKILL.md` must keep the three claims separate** — `deliver` proves the deterministic checks, `visual-check` proves bounded browser behaviour, and whether the artifact is any good remains a human judgment the tool never claims.
- Name the counterfeits: no `overflow:hidden`, no clipped content, no internal scroller, no reduced typography to pass the gate.

- [ ] Steps 1-5 as above.
